# v1.1 Plan semanal y rediseño — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a weekly training plan (API + app) and redesign the plan, workout detail and player screens following the Fitify-like layout in the spec.

**Architecture:** The plan is a per-user JSON document synced exactly like templates (client UUID, idempotent PUT/DELETE, included in `/api/sync`). The app derives week/day status locally from plan + sessions (pure functions). Screens are rebuilt on the existing player engine (steps/reducer unchanged except where noted).

**Tech Stack:** Laravel 13 + Pest (API, `~/Projects/workout-api`); Vue 3.5 + TS + Tailwind 4 + shadcn-vue + Dexie 4 + Vitest (app, `~/Projects/workout-app`).

**Spec:** `~/Projects/workout-design/2026-11-10-v1.1-plan-y-rediseno.md` (amends `2026-11-10-workout-design.md`).

## Review Focus

1. Week boundaries: a session at Sunday 23:30 Madrid belongs to that week; `starts_on` mid-week normalizes to its Monday.
2. Two plan days sharing a template: sessions are assigned in day order (first session ✓ Día A, second ✓ Día B).
3. Plan referencing a deleted template: the day shows "Plantilla no disponible" and cannot start, never crashes.
4. Before `starts_on` / after the last week: "Empieza el dd/mm" / "Plan completado" + "Empezar otro ciclo".
5. Player landscape: no element overflows or overlaps at 2400×1080.

**Interfaces — Produces:** document
`{"id","name","starts_on":"YYYY-MM-DD","weeks":12,"days":[{"template_id":"uuid","title":"Intervalos de fuerza"|null}],"updated_at","deleted_at"}`;
`PUT /api/plans/{uuid}` (201 new / 200 existing, restores deleted; 404 other user's or non-uuid), `DELETE /api/plans/{uuid}` (204, idempotent); `/api/sync` returns `plans` (array).

Rules (422 with dotted keys): `name` 1-255; `starts_on` strict `YYYY-MM-DD` real date, stored as the Monday of its ISO week; `weeks` 1-52; `days` 1-7 items; `template_id` uuid of a template of the same user (may be soft-deleted → accepted); `title` null or ≤255.

### Task 2: API — `plan:bootstrap` command

**Files:** Create `app/Console/Commands/BootstrapPlan.php`, `app/Application/Actions/Training/BootstrapPlan.php`, `tests/Feature/Training/BootstrapPlanTest.php`.

**Interfaces — Consumes:** `WorkoutPlan`, `UpsertPlan` (Task 1). **Produces:** `php artisan plan:bootstrap {--user=} {--weeks=12} {--current-week=11} {--name="Aumento de peso corporal total"} {--days="Intervalos de fuerza,Series de fuerza,Tabata,Series de fuerza"}`.

Behaviour: for each day title, pick the most recent session (source `fitify` or `app`) whose `name` equals the title (ignoring a trailing ` · dd/mm`) and whose `template_id` is not already taken by an earlier day; reuse that template (rename to the title); fail clearly if none. Soft-delete the user's other templates whose name ends in ` · dd/mm`. Create or replace (same id if a plan exists) the plan with `starts_on` = Monday of the current Madrid week minus `(current-week - 1)` weeks. Idempotent: running twice leaves the same result. Prints a summary table.

- [ ] Tests: picks latest per title; two "Series de fuerza" days get the two latest distinct templates; renames; archives the rest only (not plan templates, not user-created ones without date suffix); `starts_on` math; idempotency; missing title error.
